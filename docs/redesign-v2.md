# CardNest 重新規劃（v2）

> 狀態：規劃稿，還沒有動任何程式。目的：停止「一直修一直補」，改成一套你能自己驗算的模型。
> 示意畫面見 `docs/mocks-v2/`（六張圖，數字為示意資料）。

## 1. 為什麼要重做（診斷）

現在的帳單算法試著「自己推算銀行的帳單」，但資料不完整（信件漏抓、入帳日差一天、台新永豐信件加密、退款與點數折抵進不來）。於是同一張卡同時有幾個真相：

| 現在的數字 | 來源 |
|---|---|
| App 預估 | 刷卡紀錄加總 |
| 銀行實際 | 手動校準 |
| 剩餘 | 帳單 − 部分繳款 |
| 目前累計 | 結帳日後刷卡 |
| 卡費預估、可刷額、本月餘額 | 規劃頁另外三套 |

互相對不上時就再加一條規則（去重、部分繳款、上期未繳、校準）。每條單獨合理，疊起來沒人說得清楚為什麼是 34,277。

**結論：問題是結構，不是 bug。換成銀行怎麼算就怎麼算。**

## 2. 核心原則

1. **銀行說了算。** 要繳多少，只看銀行帳單與你實際繳的錢，不拿刷卡紀錄推算。
2. **刷卡紀錄只負責「提高警覺」。** 它漏抓只會讓警覺數字偏低，不會讓待繳算錯。
3. **每個數字只有一個定義、一個算式。** 首頁、規劃、提醒用同一份。
4. **資料不只存本機。** 本機為主，自動備份到你自己的 Google 帳號（已做，PR #39）。
5. **舊資料不碰。** v2 用新的儲存鍵，轉換前先備份；不滿意就退回。

## 3. 資料模型

只有六種東西：

| 實體 | 欄位 | 說明 |
|---|---|---|
| 卡片 Card | 名稱、末四碼、結帳日、繳款寬限天數、額度、年利率（預設 15%） | 設定一次 |
| 帳單 Statement | 卡、結帳日、到期日、**本期應繳總額**、最低應繳（選填）、本期新增（選填） | **銀行給的數字**，每張卡每月輸入 1～2 個數字 |
| 繳款 Payment | 卡、日期、金額 | 你繳了多少，一筆一筆記 |
| 刷卡 Charge | 卡、日期、入帳日、金額、名稱、類型（消費／退款） | 來自信件匯入與補登，只用於警覺與對照 |
| 固定扣款 Recurring | 訂閱或分期、卡、月額、剩餘期數、結束月 | 設定一次 |
| 規劃 Plan | 月收入、發薪日、必要支出項目、儲蓄目標 | 設定一次 |

**刪除：** 每期帳單週期（`billingCycles`）、校準、`paidAmount`、`amountIsActual`、四套重複的卡費合計、對帳「調整項」。

## 4. 算式（全部）

銀行的「本期應繳總額」已經包含上期沒繳完的錢和利息，所以**不會同時存在兩期未繳**，部分繳款、上期累加、重複的一期都自然消失。

1. **待繳（每張卡）** = 最新一份帳單的應繳總額 − 該結帳日之後的所有繳款（不低於 0）
2. **狀態**：待繳 = 0 → 已繳清；到期日前 → 未到期；過了到期日且已繳 ≥ 最低應繳 → **循環中（計息）**；過了到期日且已繳 < 最低應繳 → **逾期**
3. **目前刷卡**（每張卡）= 最新結帳日之後的刷卡（消費 − 退款）
4. **每月固定扣款** = 所有訂閱月額 + 分期當期款；分期剩餘總負債 = 每期金額 × 剩餘期數
5. **本月還能花** = 月收入 − 必要支出 − 儲蓄 − 全部待繳 − 本月尚未入帳的固定扣款 − 目前刷卡
6. **利息估算** = 區間：下限 = 待繳 × 年利率 ÷ 12；上限 = 該期應繳總額 × 年利率 ÷ 12（標明「估算，以帳單為準」）
7. **警戒等級**只用三個訊號：還能花 < 0、有循環中、固定扣款 ÷ 月收入 > 20%。0 個＝綠，1 個＝黃，2 個＝橙，3 個＝紅。

## 5. 畫面

導覽仍是三格：**現況｜記錄｜更多**。

- **現況**：待繳帳單、本月還能花、每月固定扣款，三個數字加一個行動（先繳哪張，旁邊有「全額繳清／部分繳款」）。狀況良好時警告全部收起。
- **記錄**：刷卡一筆一行，補登／退款。
- **更多**：卡片與帳單（每張卡的帳單與繳款紀錄）、固定扣款（含未來 12 個月時間軸）、規劃、設定（含備份與換機連結）。
- **帳單出來了**：結帳日後，現況出現一行「國泰 10/26 帳單出了嗎？」，點開輸入應繳總額與到期日。輸入時同時對照刷卡紀錄，顯示「信件可能漏抓 X 元」（只是資料品質提示，不影響待繳）。

## 6. 取代什麼

| 現在 | v2 |
|---|---|
| 校準、對帳 | 輸入帳單（一個動作）＋漏抓提示 |
| 部分繳款、改回未繳、已繳按鈕 | 記一筆繳款；已繳 = 記一筆全額繳款 |
| 逾期 | 循環中／逾期分開顯示，循環中顯示利息 |
| 本月餘額、可刷額、卡費預估 | 本月還能花（一個） |
| 目前累計刷卡（主數字） | 降為每張卡的小字，只做警覺 |

## 7. 轉換與風險控制

- v2 用新的儲存鍵 `cardnest_v2`；v1 不刪、不改。
- 轉換前先自動備份一份整份資料到雲端。
- 轉換前跑「試算報告」：列出你每張卡轉換後會看到的數字，你核對無誤才切換。
- 卡片、刷卡、訂閱、分期、規劃資料直接帶過去。
- **帳單無法自動轉換**（舊資料不知道每期金額是新增還是含上期），所以每張卡要你輸入最新一份銀行帳單的應繳總額與到期日，並補記自那之後的繳款。每張卡約 1 分鐘。
- 任何時候不滿意，刪除 v2 鍵即回到 v1。

## 8. 階段（每一階段都可以單獨驗收、單獨退回）

| 階段 | 內容 | 驗收 |
|---|---|---|
| 0 | 雲端備份（已完成，PR #39） | 備份分頁有資料，新手機能還原 |
| 1 | 核心算式（純函式、無畫面）＋轉換試算報告 | 用你的真實案例寫測試：國泰兩期（16,308 已繳 7,240、25,209）、富邦 2,596、台新；每個數字都能手算驗證 |
| 2 | 現況＋卡片與帳單＋輸入帳單與繳款 | 現況三個數字等於你拿銀行帳單手算的結果 |
| 3 | 固定扣款頁、部分繳款利息、新增分期前檢查 | 能說出每月固定扣款，誤差 ±10% |
| 4 | 規劃：發薪日分配、目標、月度檢視 | 首頁與規劃頁用同一個「還能花」 |
| 5 | 移除舊程式碼 | 刪掉的檔案清單與行數 |

## 9. 需要你決定或提供

1. 25,209 是「本期新增」還是「本期應繳總額」？請看國泰 10/26 帳單。（這決定階段 1 的第一個測試案例。）

3. 月收入是固定的嗎？薪資帳戶餘額要不要記？（階段 4 才需要。）
4. 台新、永豐：信件加密進不來，只能補登與輸入帳單，可接受嗎？

## 10. 我沒有驗證的

- 專家顧問提供的利率上限、最低應繳比例、警戒門檻都是經驗值，沒有逐項查證來源；實作時會做成可設定。
- 各銀行對循環利息起算日不同，利息只做區間估算。
- 這份方案還沒有在你的真實資料上跑過；階段 1 的試算報告就是為了這件事。
