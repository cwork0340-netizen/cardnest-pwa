# 國泰多筆消費通知修正

`CathayMulti.gs` 是可加入既有 Apps Script 的獨立修正模組，不是整份舊專案的替代品。
它使用 HTML 表格欄位逐筆解析，保留空商店、完整商店名稱、授權日期與實體卡號。
行動卡號不拿來配對實體卡。格式不完整時整封暫停，不會靜默接受部分交易。

## 套用順序

1. 先保存線上 Apps Script 的現行程式、觸發器與設定。
2. 將此模組加入同一專案，Script Properties 設定 `CARDNEST_SHEET_ID` 為既有消費記錄試算表 ID。
3. 執行 `previewCathayRecovery`。只讀最近 30 天信件（包含已標示匯入者），不修改 Sheet 或 Gmail。
4. 用真實信件核對解析筆數、日期、卡號與總額；先處理預覽中的 failures。
5. 部署 App 的逐筆匯入修正，再執行 `recoverCathayNotifications`。第一次有寫入時會先複製消費紀錄分頁備份。
6. 將既有定時匯入函式的國泰處理改由 `recoverCathayNotifications` 負責，其他銀行流程保留。
   必須移除舊流程的國泰搜尋條件／分派，避免兩個 writer 同時寫入。
   不要另設一個排程與舊國泰 writer 並行。
7. 在 App 重新匯入，核對補回筆數與金額；再匯入一次應為新增 0 筆。

## 資料相容性

- A–I 欄順序不变；J 為每筆交易識別碼，K/L 為修正前日期與類型。
- 舊資料以同信件、卡號、金額、商店作唯一比對，保留匯入時間與人工填寫的入帳日。
- 名稱不一致或有多個候選時停止該封信的寫入，留下診斷，不猜測補筆。
- App 只有在舊交易欄位仍等於 K/L 的修正前值時，才更新錯誤日期與類型。
- 既有手動修改的金額、備註、日期不覆寫；識別碼獨立於這些可編輯欄位。
- 舊版只有整封信的删除記號。單筆信件的删除維持；多筆信件無法還原刪除的是哪筆，
  重新匯入可能補回曾刪除的列，回補前須核對。新版逐筆删除記號可保留。
- 沒有 J 欄的舊表仍能讀取，但同信件內日期／商店／金額全相同的兩筆，必須先由新解析器產生不同 J 值。
- 單次最多讀取 500 封對話。到上限會明確記錄，應縮小區間後核對，不視為全量完成。

## 驗證範圍

Vitest 涵蓋四筆通知、空商店、行動卡號、巢狀表格、同額兩筆、日期錯誤、部分解析失敗、
舊第一筆升級、補回三筆、重跑零新增，以及 Sheet 到 App 的回補流程。
測試資料為合成範例；仍須在個人帳號驗證真實通知 HTML 後才替換定時流程。
